# Validation Workspace

This folder is for Week 1 validation work.

It is not final onboarding documentation. Its purpose is to help turn early onboarding attempts into validated guidance by capturing:

- real commands that were tested
- actual outputs and failures
- confusion points for beginners
- evidence that later docs should include or clarify

This validation work is part of the project's core value. Official documentation provides reference information, while these logs help identify where real beginners slow down, fail, or make incorrect assumptions.

## Files

- [validation-log-template.md](validation-log-template.md): reusable log template for each test attempt
- [validation-checklist.md](validation-checklist.md): structured checklist for environment, node setup attempt, and RPC attempt
- [beginner-failure-detection-checklist.md](beginner-failure-detection-checklist.md): signs to watch for during real onboarding
- [test-command-pack.md](test-command-pack.md): safe commands and capture patterns for collecting validation evidence

## How To Use This Folder

1. Start with [test-command-pack.md](test-command-pack.md).

   Run the generic environment validation commands exactly as written.

2. For CKB-specific testing, use only commands from official sources.

   Do not rewrite them from memory. Paste the exact command you tested into the log template.

3. Create one log entry per attempt.

   If a command fails twice in different ways, record both attempts separately.

4. Capture confusion as carefully as failure.

   A step can be technically successful and still be a poor onboarding experience.
